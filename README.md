# Jumbly

A swipe-to-spell word grid game for the browser. Pick a 4×4, 5×5 or 6×6 grid and a round length
(30 s to 3 min, or no limit when playing alone), then drag through neighbouring letters to spell
words of three letters or more. Play solo, or duel a friend live on the same board with a synced
3-2-1 start.

## Layout

| Path | What it is |
| --- | --- |
| `src/page.html` | The whole app: markup, styles, game, duel protocol, network transports |
| `src/core.js` | Dictionary loader, board generator, solver, scoring (no DOM; inlined at build) |
| `src/words.js` | Packed word list, generated by `tools/build-dict.mjs` |
| `tools/build.mjs` | Builds `dist/artifact.html` (claude.ai artifact) and `site/` (static site) |
| `site/` | Ready-to-host copy: `index.html` + `words.js`, nothing else needed |
| `test/` | Playwright end-to-end tests |

```bash
node tools/build.mjs
```

```bash
node test/serve.mjs 8080
```

## How it plays

- **Input**: swipe across letters; or tap letters one by one and tap the last one again; or type
  the word and press Enter. Slide back over the previous letter to undo it.
- **Scoring**: 3 letters = 1 point, then 2, 4, 7, 11, 16, 22 … (each extra letter adds one more
  than the step before). In a duel, a word both players found scores face value for each; a word
  only one player found scores double.
- **Boards**: letters are drawn by weighted frequency with 31–40 % vowels and limits on repeats
  and rare letters, then solved; a board is dealt only if it has enough words and enough long ones.
  `Qu` is one tile.
- **Words**: the ENABLE list (public domain), 3–16 letters, about 170,000 words.

## Live duels

Each player publishes one small state object to a shared room; everyone in the room sees
everyone's latest state. The host deals the board and names a start time on its own clock. The
guest measures the difference between the two clocks with a few ping/pong round trips, so both
countdowns reach zero together and both rounds end together. When time is up each side publishes
its word list and both tally locally (incoming words are checked against the board).

The room is carried by one of three transports, chosen automatically:

| Where the page runs | Transport | Who can join |
| --- | --- | --- |
| claude.ai artifact | the artifact's live `room` (presence only) | People signed in to Claude who have been added to the artifact. A public link alone only allows solo play |
| Any static host (`site/`) | a public MQTT broker over WebSocket | Anyone with the link |
| `?net=local` | `BroadcastChannel` | Tabs of the same browser (for testing) |

The static-site relay uses free public MQTT brokers (EMQX, HiveMQ, Mosquitto test servers, tried
in that order). They carry only room codes, nicknames, and word lists, and come with no uptime
promise; point `BROKERS` in `src/page.html` at your own broker for anything serious.


```bash
node test/duel.mjs
```

```bash
node test/extras.mjs
```

`WW_NET=room node test/duel.mjs` runs the duel against a stand-in for the claude.ai room API, and
`WW_NET=relay WW_BROKER=ws://127.0.0.1:18883 node test/duel.mjs` runs it through a local MQTT
broker.
